# Health Prediction Records

A small Python application to manage patient blood-test records (CRUD) and generate an AI-based health-risk remark for each patient.

- **Backend:** Python, SQLite (`sqlite3`)
- **Frontend:** Streamlit
- **AI:** Google Gemini API, with a rule-based fallback if the API is unavailable

> The AI remarks are a screening aid, not a medical diagnosis.

## Features

- Create, read, update and delete patient records
- Validation: name, email format, date of birth (`dd/mm/yyyy`, must be a real date, not in the future), numeric blood values within plausible ranges, duplicate email detection
- Remarks are generated by the AI only after the data passes validation, and the source of each remark (Gemini or fallback) is stored with it
- Records persist in a local SQLite file

## Project structure

```
app.py          Streamlit UI (pages: Add, Records, Edit, Delete)
services.py     Business logic: validate -> duplicate check -> AI -> save
validators.py   All input validation rules
ai_service.py   Gemini API call + rule-based fallback
database.py     SQLite access (the only module that runs SQL)
tests/          pytest suite that runs the 10 assignment rows
```

## Setup

```bash
pip install -r requirements.txt
cp .env.example .env        # then add your own GEMINI_API_KEY (free: https://aistudio.google.com/apikey)
streamlit run app.py
```

Without an API key the app still works and uses the rule-based fallback; the "Remarks source" column shows which one produced each remark.

## Run the tests

```bash
pytest -v
```

## How a record is saved

1. `validators.validate_patient` checks every field and returns all errors at once.
2. `services` checks that the email is not already used (case-insensitive; also enforced by a `UNIQUE` constraint in the database).
3. `ai_service.predict` builds a prompt from age and blood values, calls Gemini, and parses a JSON reply (`risk`, `remarks`). On any failure it falls back to `rule_based_prediction`.
4. `database.insert_patient` stores the record. DOB is stored as ISO `yyyy-mm-dd` and displayed as `dd/mm/yyyy`.

On edit, the AI is called again only if the date of birth or a blood value changed.

## Notes on validation

- Dates typed as `dd.mm.yyyy` or `dd-mm-yyyy` are converted to `dd/mm/yyyy` before checking.
- Reference ranges used in the prompt and fallback: glucose 70-99 normal, 100-125 prediabetes, 126+ diabetes range; haemoglobin about 12-17.5 g/dL; total cholesterol below 200 desirable, 240+ high.
- No API keys are stored in the repository. `.env` and `*.db` are git-ignored.
